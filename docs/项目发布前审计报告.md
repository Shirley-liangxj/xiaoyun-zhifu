# 小云智服项目发布前审计报告

> 审计时间：2026-10-15  
> 审计对象：`D:\xiaoyun` 当前源码、评测集与可运行配置  
> 审计目的：先确认项目是否具备可被 HR/面试官验证的完整闭环，再决定补齐范围。本文只记录审计阶段事实，不把计划写成已完成。

## 1. 结论先行

当前项目不是“没有功能”，而是已经有买家端、坐席端、知识库、RAG 评测和 Agent 控制层，但发布前仍有五项 P0 阻断：

1. 没有独立、可重复的 Agent 全链路评测，无法证明工具选择、参数抽取、转人工和高风险拦截是稳定的。
2. 退款确认仍落在进程内 JSON，服务重启或多实例时人工审核状态不可靠。
3. `messages.is_sent` 同时表示“买家端 AI 已展示”和“坐席采纳建议”，Dashboard 的 AI 采纳率因此不具备严格业务含义。
4. 知识缺口解决接口在索引失败时仍把状态写成 `resolved`，会造成“看板显示已解决、实际检索仍不可用”的假闭环。
5. RAG 评测把关键词覆盖率命名为 `answer_accuracy_rate`，会把“检索文本包含关键词”误读成“生成回答正确”。

当前可以保留的事实：

- 当前正式回归集为 40 题；旧 67 题只作为历史材料，不作为当前发布口径。
- 现有 40 题题库测试已通过 3/3；这只证明题库结构，不代表 Agent、API 或页面链路通过。
- 代码层已存在高风险前置拦截、工具白名单、退款试算不自动打款、低置信转人工和人工确认卡；这些是可继续复用的基础。
- 当前工作区存在用户未提交改动，本次审计不覆盖、不回滚这些改动。

## 3. P0 / P1 / 边界分类

### P0：发布前必须完成

| 编号 | 问题 | 影响 | 代码证据 | 验收标准 |
|---|---|---|---|---|
| P0-1 | 缺少独立 Agent 评测 | 无法证明“一个完整任务一路看到机制和价值” | `backend/app/agent/agent_loop.py` 只有线上入口；无 `agent_cases`/Agent runner | 至少覆盖工具选择、参数抽取、转人工、高风险、退款确认、异常/最大轮次；离线可重复；结果能由 API 返回。 |
| P0-2 | 审核状态落在 JSON | 服务重启/多实例可能丢失或覆盖退款确认状态 | `backend/app/agent/agent_loop.py` 原 `pending_confirmations.json` 路径 | 使用 `human_review_actions` 表记录 pending/confirmed、payload、时间和租户；确认接口按数据库状态幂等校验。 |
| P0-3 | `is_sent` 语义混用 | 买家自动回复会被统计成坐席采纳，Dashboard 采纳率失真 | `backend/app/models/conversation.py`、`services/public_chat.py`、`routers/stats.py` | 引入明确的建议状态/处理动作；买家自动回复不计入坐席采纳；采纳、编辑、拒绝可区分。旧数据有兼容迁移。 |
| P0-4 | 知识缺口假解决 | 索引失败时仍进入 resolved，无法形成知识闭环 | `backend/app/routers/knowledge.py:resolve_gap` 对 `index_document` 异常直接 `pass`，随后无条件 `gap.status='resolved'` | 只有文档写入且索引成功才 resolved；失败返回明确状态/错误，保留 pending，可重试。 |
| P0-5 | 指标命名不实 | 面试或作品集会把关键词覆盖误讲为回答正确 | `backend/app/services/eval_runner.py` 的 `answer_accuracy_rate` | 改成 `keyword_coverage_rate`（及 per-category 同名）；UI、Schema、文档同步，明确不等于生成答案正确。 |
| P0-6 | 完整端到端验收缺失 | 单测通过仍可能页面主链路断裂 | 当前只有题库测试 | 至少完成一条：客户提问 → 检索/工具 → 低置信或高风险分叉 → 坐席看到状态 → 采纳/接管；保存可复核证据。 |

### P1：P0 后补齐

- 为 Agent trace 增加更稳定的 run_id、case_id 与可读的失败原因，便于作品集引用。
- 将知识缺口的索引错误、重试次数、最近一次错误写入结构化字段/日志，而不是只依赖异常文本。
- 前端评测页增加 Agent 评测区和指标口径说明，避免把 RAG、Agent、HITL 混成一张“准确率”卡片。
- 将旧 67 题标注为历史版本，避免页面、README、作品集继续出现“当前 67 题”的歧义。
- 为真实线上环境补充构建和页面冒烟记录；外部 LLM 真实评测需要另行授权，不在本次离线验收中默认执行。

### 明确不纳入本次发布承诺的边界

- 不承诺真实退款、真实打款、真实支付回调；`calc_refund` 只做试算，退款需人工处理。
- 不把离线 mock Agent 评测写成真实大模型工具调用准确率。
- 不把关键词覆盖率写成生成式回答事实正确率。
- 不新增虚构的商业化收入、客户数、线上转化或生产 SLA。
