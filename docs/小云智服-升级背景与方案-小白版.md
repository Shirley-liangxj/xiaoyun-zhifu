# 小云智服 升级背景与方案说明（小白版）

> 给谁看：转行 AI PM、自称小白的 Shirley。
> 这份只讲"为什么升级 + 改哪些方面 + 你该补的知识"，不写代码、不改简历。

---

## 一、为啥要升级（不升级会怎样）

你现在的项目是个**纯问答客服**：用户问 → 检索资料 → AI 答 → 答不准转人工。

这套在 2023–2024 是前沿，但 **2026 年招聘看的是"能办事的 Agent"**——不只是"答得对"，还要"能调工具、能分步干活、出错有人管"。

两个独立来源都印证了"显浅"这个结论：
- 你抖音那 8 个视频里，第 1 个就是《电商智能客服 Agent 从 0～1》，第 8 个讲"为 AI 犯错设计兜底"——本质都是 Agent 管控层思想。
- 外部求职辅导（方圆老师）看了你简历也诊断："项目偏原型、落地深度弱、无业务数据"。

**不升级的后果**：简历上写"我会 RAG" ≠ "我能做 AI 产品"。面试官看完觉得——这姑娘只会搭个问答 Demo，浅。

## 二、改哪些方面（4 刀，每刀解决一个"浅"）

| 里程碑 | 改啥 | 改完为啥不浅了 |
|---|---|---|
| **M1 意图路由** | 用户消息先分类（咨询/查询/操作/转人工）再处理 | 从"无脑直答"变"有判断"——这是 Agent 和客服机器人的分水岭 |
| **M2 工具注册表 + 真能跑的小工具** | 接 2 个工具：查订单（mock 数据）、算退款（规则函数） | 消除"无系统对接"的玩具感——系统终于能"办小事"了 |
| **M3 会话轨迹审计** | 每轮记 input→意图→工具→output，可回放 | 这是 Agent 管控层最值钱的思想，也让你 67 题 badcase 复盘有抓手 |
| **M4 统一入口** | 串成一次对话循环，给用户"执行计划卡"而非一句话 | 正面接面试官"任务完成率怎么算"的拷问 |

**核心思路**：在现有 RAG 底座上**加一层控制层**，不是推倒重来。老底子（67 题评测 / 0.6 阈值 / 转人工 97%）全保留并强化。

## 三、小白补课（你没说上、但我必须补的点）

1. **"落地深度"到底指啥**：招聘里"落地"= 真有人用 / 真接业务系统 / 真有业务指标。你缺的是这层，不是缺算法。所以升级补的是"办事能力 + 可解释"，不是更深模型。

2. **为啥"加控制层"比"重做"聪明**：复用你已有的 RAG 底座，风险低、出活快、每句都能讲清。重做反而容易露馅（你手上没有真实订单/物流系统）。

3. **Mock 不造假**：演示用的假订单数据，面试如实说"是演示 mock 数据"。诚实说 mock 比编真实 API 安全一万倍。

4. **评测集是你的护城河**：67 题 / 0.6 阈值 / 97% 转人工判断——这是别人拿不出的真东西，升级时**强化不是丢掉**。

5. **简历"对标层"概念**（抖音视频 7 提过）：作品集分 4 层，你稳在第 3 层"完整 AI 产品能力层"，但简历用了第 1 层的语气在写——这是最大的浪费。

6. **双轨并行，别停投递**：边升级项目边继续投中小厂。投递中遇到的追问，反过来告诉你该补哪刀。闭门等"完美"会错过秋招岗位。

7. **Harness 是"思路"不是"依赖"**：DeepSeek Harness 是 v0.1 预览版、官方称不适用生产。我们学它的"控制层思想"，不硬塞它的框架——避免引入不稳的依赖导致 Demo 跑不起来。

## 四、升级后你项目的一句话定位

> **「从知识问答型 RAG 升级为带工具调用 + 人机协同的轻量售后 Agent」**

老底子全留，新东西补上趋势缺口。面试讲到这句，你既踩中了 2026 的节奏，又每句话能演示、能被追问住。
