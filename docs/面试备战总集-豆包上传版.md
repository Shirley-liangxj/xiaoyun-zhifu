## 小云智服（作品集通用备战）

# 小云智服 — AI PM 面试备战文档

> 适用场景：社招初级 AI PM 岗作品集讲解 / 面试官深挖>   
> 定位：AIPM-Wiki（archlizheng）定义的「路径 B 独立 Demo」——证明的不是"模型多强"，而是"作为 AI PM 怎么定义问题、设计兜底、用评测闸门把控质量"

---

## 0. 一句话定位（开场必说）

小云智服是面向**服饰电商的 AI 售后客服**（RAG + 大模型）。我用它想讲清楚一件事：**AI 客服的核心风险不是"答不对"，而是"该转人工时硬撑、或不该转时瞎转"**。所以我的设计重心放在分层兜底 + 可量化的转人工判断，而不是堆模型能力。

---

## 1. 已落地的产品闭环（能演示）

| 模块   | 能力                                   | 说明               |
| ---- | ------------------------------------ | ---------------- |
| 买家端  | RAG 问答 + 低置信气泡「这个回答不满意？转人工」+ 底部常驻转人工 | 体验闭环，不只一个聊天框     |
| 坐席端  | 待人工列表、AI 建议采纳 / 回复                   | 买家↔坐席真正打通，不是空壳   |
| 分层兜底 | 阈值 0.6 + 拒答话术 + 转人工                  | AI 不能硬撑时的出口      |
| 容错   | 密钥 / 外部服务降级                          | LLM 调用失败走拒答，系统不崩 |
| 冷启动  | 空库自动 seed + reset-demo               | 解决"打开全是空白"的体验死穴  |

## 2. 评测证据（最强卖点 —— 本次升级产出）

> 这是作品集最缺的"判断证据层"。没有它，Demo 只是 Demo；有它，才叫"PM 用数据把控质量"。

**整体指标（threshold=0.6，company_id=1，实测）**

| 指标            | 数值           | 怎么解读                            |
| ------------- | ------------ | ------------------------------- |
| 总题数           | **67**       | 分层抽样，不是 17 题拍脑袋                 |
| 回答准确率         | **91.1%**    | expected=answer 且检索命中+关键词覆盖≥50% |
| **转人工判断准确率**  | **97.0%**    | 实际行为与期望行为一致的比例（核心指标）            |
| 转人工准确率（超出范围类） | 90.9%        | 该转的转对了多少                        |
| 误转            | 1（占应答题 1.8%） | 本该答却转了——极低，体验损失小                |
| 漏转            | 1（占应转题 9.1%） | 本该转却答了——可控，且有误判兜底话术             |
| 检索命中率         | 100%         | 知识库召回稳定                         |

**分层表现**

| 分类         | 题数 | 行为准确率 | 回答准确率 | 误转 | 漏转 |
| ---------- | -- | ----- | ----- | -- | -- |
| 退换货        | 10 | 100%  | 90%   | 0  | 0  |
| 物流         | 10 | 100%  | 100%  | 0  | 0  |
| 质量         | 10 | 100%  | 80%   | 0  | 0  |
| 支付         | 10 | 100%  | 80%   | 0  | 0  |
| 通用         | 10 | 90%   | 100%  | 1  | 0  |
| 超出范围       | 11 | 90.9% | —     | 0  | 1  |
| 尺码（原17题）   | 3  | 100%  | 100%  | 0  | 0  |
| 售后政策（原17题） | 3  | 100%  | 100%  | 0  | 0  |

**为什么这组数字重要（面试话术）：**

> "我特意把『转人工判断准确率』单独拎出来当核心指标，因为客服场景最严重的失败不是答错，而是该转不转。97% 的判断准确率 + 仅 1.8% 误转，说明我的阈值 0.6 是经评测校准的，不是拍的——这比单纯说'回答准确率 91%'更有 PM 含量。"

## 3. 成本 / 延迟基线（估算，附依据）

> 面试官必问"花多少钱"，以下是**生产预算口径**的估算，不是开发期实际支出。

- **模型**：智谱 GLM。开发期用免费档（实际支出 ≈ ¥0）；生产按付费档估算。
- **单轮 token**（RAG 场景典型值）：输入 ≈ 2500 token（system + 检索上下文 + 多轮历史），输出 ≈ 300 token。
- **单轮成本**（按 2026-08 智谱公开定价）：
  - GLM-4-Air 档：≈ **¥0.004 / 轮**
  - GLM-4.6 档：≈ **¥0.012 / 轮**
- **单会话成本**（按 4–6 轮含 AI 建议）：≈ **¥0.02 – 0.07**
- **延迟**：首 token 0.8–2s，整答 1.5–4s（取决于上下文长度）。
- **对比锚点**：一个 AI 兜底 + 坐席建议的会话，单均模型成本远低于一名人工客服的单均人力成本，价值在"降人工介入率 + 提坐席效率"。

> 标注：开发期用智谱免费 API，实际支出 ≈ 0；上表为生产容量规划口径，模型档位与 token 数均为估算，面试时说明假设即可。

## 5. 多租户演进 / 「给我 3 个月」路线图

1. **评测自动化**：CI 接 golden set，每次发版跑准确率闸门，不达标不发布。
2. **真实数据回流**：上线后收集真实 query + 转人工结果，反哺评测集与阈值。
3. **多租户隔离**：按 company_id 做知识库 / 索引 / 配额隔离，支持 SaaS 化。
4. **人效看板**：AI 建议采纳率、坐席处理时长、deflection rate、CSAT 四件套监控。

## 6. 合规说明（PII / 个保法）

- 对话含客户姓名、订单号等个人信息，属敏感个人信息范畴。
- 设计原则：存储加密、字段最小化、设定留存期限、超期清理。
- 默认不用于模型微调训练（除非获得商家 + 用户授权）。
- 转人工时仅传递必要上下文，避免全量对话裸奔给坐席。

## 8. Bad case 截图清单（3 张，复现脚本见下）

### Badcase 2 — 转人工闭环（买家转 → 坐席端「待人工」可见 → 采纳建议回复）

- 预期 UI：系统识别为超出范围，给拒答话术并引导转人工，**不编造答案**。
- 截图点：截到拒答话术 + 转人工引导那一屏（证明"不乱说"）。

> 基本上全程都参与了。最开始是需求阶段，跟销售访谈跟岗，整理高频场景排优先级，跟产品经理对齐先做哪两块。然后设计阶段，画原型写 PRD，过了评审改了几版。开发阶段最长，每天站会跟开发对接，给他们讲 Prompt 的设计思路，帮着整理话术知识库的分类。测试阶段写测试用例跟测试一起测，收集不好的案例反馈调优。最后验证阶段，先小范围内测收反馈改版，再扩大试用。

### Q9：你都跟谁对接？

> 挺多的，产品经理每周对需求和评审；后端开发每天站会对接，功能实现、Prompt 调优、接口联调都是跟他们；还有一个测试，对用例和跟 bug；销售主管对需求访谈和场景确认，最后验收也是他；一线销售做用户访谈和内测反馈。

> 三类吧。第一类是销售跟进的数据，从 CRM 导出来做基础分析用来排优先级；第二类是话术使用的数据，内测的时候统计的复制率、修改率，看推荐效果好不好；第三类就是 badcase 数据，把话术不准的案例按"场景不对、语气不对、信息缺了"分类，指导调 Prompt 的方向。

### Q11：遇到最大的困难是啥？怎么解决的？（必问）

> 最大的困难就是第一版话术推荐效果很差，销售说太通用了不像人说的。当时我也有点慌，后来就先不急着改，把不好的案例全导出来一条一条看，分类之后发现大部分是语气不对、小部分是缺客户信息、还有少量是场景判断错了。  
> 然后我拉着销售聊，问他们觉得啥叫"准"，他们说至少得跟客户刚才说的意思对上。我就把这个变成具体的标准，跟开发一起重新设计 Prompt，加了行业词库，还有不同场景的语气设定。改完之后内测反馈好多了，销售说这次推荐的能用了。这件事给我最大的感受就是，别自己闷头想，先搞清楚用户觉得啥叫好，再找技术方案。

### Q12：跟开发有过分歧吗？怎么处理的？

> 有过。做话术推荐的时候，开发说直接给 10 条让销售自己选最省事，但我觉得不行，因为第一轮试用的时候销售明确说过给多了反而不知道看哪条。我也没跟他硬争，就把当时销售的反馈截图发群里了，销售原话是"3条我还能挑一下，10条我就直接放弃了"。后来我们就折中，给 3 条，按置信度从高到低排，如果都低就提示建议人工判断。开发也接受了，我觉得主要是拿用户反馈说话，不是拿"我是产品"压人。

## 六、项目深挖（小云智服，90%问）

### Q14：介绍一下小云智服

> 介绍一下小云智服

### Q15：RAG 是啥？

> RAG 就是检索增强生成。简单说就是大模型本身知识有限还会胡说，所以先从企业的知识库里搜相关的文档，把搜出来的内容跟用户的问题一起传给大模型，让它基于搜到的内容来回答。好处是回答有依据能溯源，知识库更新了不用重新训练模型。

### Q16：你怎么判断 AI 功能做得好不好？

> 我搭了一套评测的东西，主要看两个指标：一个是溯源准确率，就是 AI 回答引用的知识库内容对不对，我批量跑一些测试题人工标注来算；另一个是 badcase 回归，每次改了 Prompt 或者知识库之后跑一遍测试集，确保之前答对的不会改错。  
> 我攒了一套 **67 题的分层评测集**（按场景和难度分层的），跑下来回答准确率 90% 出头、转人工判断准确率接近 97%。**但要说明这是 demo 评测集跑出来的，不是线上真实 query 分布，真实解决率要上线回流数据才算。**

### Q17：AI 调用成本太高怎么办？

> 几个方向吧，选模型的时候就把成本考虑进去，我当时选的是性价比高的模型；然后简单的问题用小模型，复杂的才调大模型，做分级；还有常见问题缓存起来，重复的问题不用每次都调；另外 Prompt 也尽量精简，减少不必要的 token 消耗。

### Q18：有没有你觉得不该用 AI 的场景？

> 有啊，做小云智服的时候最开始我想把工单分配也做成 AI 自动分配，但后来想了想，售后工单类型就固定那几种，用规则引擎就能分准，而且规则比 AI 稳定、成本低、还能解释清楚为啥这么分。所以最后工单分配用的规则，AI 只做问答推荐。我觉得不是啥都要套 AI，产品经理得判断什么时候该用什么时候不该用。

### Q19：项目里最大的挑战是啥？

> RAG 检索效果不好，用户问的问题知识库里明明有，但就是搜不到。最开始我是按固定长度切片的，效果很差，后来改成按语义段落切，就是一篇文档按小标题和段落的自然分界来切，准确率提升了不少；还加了关键词权重，让标题和高频词权重高一点。前前后后调了一周左右才调到比较满意的效果。

## 八、场景题（记思路，别背，HR 可能即兴问）

> 核心思路：先搞清楚原因 → 再想替代方案 → 实在不行就看优先级。用自己的话说。

**Q23：开发说你这个需求做不了怎么办？**  
先问清楚为啥做不了，是技术真不支持还是排期不够还是没数据。如果是排期问题，就看看能不能换个简单点的方案（比如技术上可以改成预生成而不是实时算）。如果确实做不了，就判断是不是核心功能，核心的拉 mentor 一起评估挤排期，不是核心先放一放。最后不管做不做都跟开发对清楚替代方案和时间。

> ⚠️ "实时改预生成"只是**举例思路**，不是你真实经历，别当成自己的事说。

**Q24：产品上线后数据不好怎么办？**  
先排查是不是数据本身的问题，埋点漏没漏、统计口径对不对、是不是延迟了。然后看是不是产品问题，用户用到哪一步流失了。最后看是不是需求问题，如果用户根本不用，那可能就不是真痛点，得重新调研。

**Q25：领导给你一个不认可的需求怎么办？**  
先搞清楚领导为啥要做，是想解决啥问题还是有数据支撑。如果还是觉得有问题，就带着方案去找他聊，不说"我觉得不对"，说"我理解是要解决 A 问题，但 B 方案可能更有效，您看哪个方向合适"。如果领导坚持就先做，但上线后我盯数据，效果不好再拿数据回来聊。

**Q26：好几个紧急需求同时来怎么排？**  
看两个维度，业务价值和实现成本。高价值低成本的先做，高价值高成本的评估后排期，低价值的直接砍。

**Q27：从 0 到 1 做新产品第一步干啥？**  
先找真实数据搞清楚问题是啥，绝不坐办公室拍脑袋。做小云智服的时候我就是先扒真实客诉一条一条标，统计出哪几类占大头，才确定先做这三块。然后画个原型找几个人看方向对不对，再动手做 MVP，不做大而全，上线跑数据再迭代。

> "主要对接四类人：销售团队（用户访谈和试用反馈）、算法工程师（确认 RAG 检索边界）、前后端开发（确认接口字段和页面交互）、测试（帮构造测试语料）。日常沟通靠每天上午 11 点站会 + 飞书随时同步，遇到拿不准的比如'提醒逻辑到底按什么规则触发'，我会拉着开发和销售代表当场定，不拖进度。"

### 8. AI 差旅智能体又做了什么？

> "这个项目更前期一点。我先做了 **50 份**内部问卷 + 深度访谈 **6 个**同事（财务、销售、高管各 2 个），画出用户画像，发现订票耗时是最大痛点。然后从公司报销系统拉了半年 **400 多行** Excel 数据，算出**人均订票耗时 15 分钟**。接着把差旅流程拆成'订机票/订酒店/同步行程/发起报销'4 个原子能力，设计了'**低于 800 元自动订，超过 800 元弹窗确认**'的人机协作边界。最后根据用户反馈把 MVP 收敛到'订机票 + 同步行程'两个核心场景，出了 PRD 和原型。"

### 9. 如果 mentor 给你一个很模糊的任务，你怎么办？

> "我会先拆解自己理解，然后去找 mentor 确认方向。比如做差旅智能体的时候，mentor 说'你去调研一下差旅痛点'，我第一周就自己拉了数据、做了问卷、出了初步画像，拿去找 mentor 对齐，他说方向对了再继续深挖。先自己消化再主动对齐，不等着喂饭。"

### 10. 进入一个新公司业务什么都不熟悉，你会怎么做？

> 参考答法："三步走：①先摸清信息——看历史文档、产品架构、现有数据口径，快速建立全局认知；②找对人——跟 mentor 和一线业务（销售/运营）聊，搞清楚'现在最大的问题是什么'而不是自己猜；③小步快跑——先接一个边界清晰的小需求跑通流程，建立信任后再碰大模块。不急于表态，先理解再输出。"

**Q4：怎么评测 AI 产品的好坏？**

> "三层维度：①**产品层**——采纳率、转化率、用户留存；②**模型层**——命中率、badcase 率、漂移检测；③**业务层**——ROI、客诉率、解决率。>   
> 我在小云智服做的就是**模型层评测**——67 题分层 golden set（按场景/难度分类）+ 阈值校准（用评测集找最佳置信度切分点）+ badcase 闭环（知识缺口写入知识库再回归）。>   
> **关键点**：评测集不能只有正面 case，**必须有对抗/边界样本**（矛盾、辱骂、超纲），不然测出来 95% 准确率上线一翻车就完蛋。"

**Q5：大模型怎么选型？**

> "**三维评分卡：效果 + 成本 + 延迟**。效果看 badcase 率+评测集命中率；成本看单次 token 价；延迟看 P95 响应时间。>   
> 阿帕奇销售助手我做过类似选型：对比了 GLM-4-Flash、Kimi、DeepSeek 三个模型，最终选了 GLM-4-Flash——**效果 80% 满足 + 成本是 Kimi 的 1/5 + 延迟可控**。如果对效果要求极高，会用更大的模型做精排，小模型做粗排，混合架构。>   
> **注意**：选型不是一次性的，要**持续 A/B 跟踪模型版本更新**（GLM-4、Kimi 每代都有大升级）。"

**Q6：你全栈开发是怎么做的？用什么技术栈？**

> "**前端 React + Vite + 你的 UI 库**，**后端 FastAPI + SQLAlchemy**，**向量检索用 FAISS 或 Chroma**，**大模型调用走 OpenAI 兼容 API（智谱 GLM）**，**部署 Docker Compose 上阿里云**，**评测脚本 Python 单文件**。>   
> 我是软工科班，能看懂、能 debug、能跟算法对齐接口；vibe coding 是提效手段，**关键架构和判断是我做的**。"

**Q7：vibe coding 追问：你代码到底写到什么程度？核心逻辑是 AI 生成的还是你写的？**

> "vibe coding 是我**写代码的加速方式**，不是替代方式。我能：>   
> ①看懂 AI 生成的代码、知道为什么这样写；②debug 错误（不是瞎试）；③设计架构（数据库表、API 接口、模块边界）；④跟算法/前端对齐接口字段。>   
> **关键判断**：什么该让 AI 写（CRUD、重复逻辑、UI 组件）、什么必须自己写（核心算法、评测逻辑、数据迁移）——这个判断是我做的。"

**Q8：你对猎豹的 Orion 大模型/智书 AI 应用有什么了解？**

> "猎豹 2016 年就进军服务机器人，Orion-14B 是自研大模型，AgentOS 是机器人大模型框架。**智书**应该是基于 Orion 的 AI 应用产品线，跟字节豆包、阿里通义、百度文心是同类。>

> 如果有幸加入，我会先深度体验智书 30+ 个核心场景，画出用户体验地图和功能优先级。"

**Q9：你的职业规划？**

## 三、面试可能问的"硬核"5 题（如果面试官是技术官）

**Q11：你了解 Agent 吗？怎么设计一个 Agent 产品？**

> "Agent = 能自主执行多步任务的 AI 系统，**核心是工具调用 + 规划 + 记忆 + 反思**。>   
> 设计一个 Agent 产品的关键是：①**原子能力拆解**（差旅 Agent = 订机票/订酒店/同步行程/发起报销）；②**人机边界设计**（什么让 AI 自主，什么必须人确认）；③**评测体系**（每个原子的成功率、badcase 收集）；④**安全护栏**（金额上限、敏感操作必须人工）。>   
> 我在阿帕奇做过差旅智能体就是按这个思路：4 个原子能力 + 800 元以下自动订、以上弹窗确认。"

**Q12：你对机器人大模型 AgentOS 有什么了解？**

> "AgentOS 是猎豹自研的机器人大模型框架，**让机器人有'大脑'**——能听懂指令、做任务规划、调用工具、控制硬件。>   
> 我没在机器人领域做过，但从 AI 产品视角看，机器人大模型的核心挑战是：①**多模态输入**（语音+视觉+触觉融合）②**实时性**（机器人要在物理世界秒级响应）③**安全冗余**（不能让机器人伤到人）。>   
> 如果有幸加入 AgentOS 团队，我会先花 1-2 周体验现有机器人产品，画出'AI 决策延迟-物理执行-安全护栏'的端到端流程图。"

**Q13：你的 67 题评测集怎么设计的？为什么是 67 题不是 100 题？**

> "**分层设计**：按场景（物流/退换货/质量/通用）+ 难度（简单直球/多轮追问/边界对抗）切分。67 题是为了**快速验证'转人工判断准不准'这个主假设**——核心不是'题越多越好'，是'分层能反映真实场景分布'。>   
> 真实 query 回流后，会扩到 200+ 题做完整评测。**评测集是个持续运营的资产，不是一次性的**。"

**Q14：如果产品上线后发现用户不爱用，怎么办？**

> "三步：①**数据诊断**——看漏斗在哪一步掉（曝光→点击→使用→留存）；②**用户访谈**——找 5-10 个典型用户聊，搞清楚'为什么不用'；③**假设验证**——挑最可能的原因改一版，小流量 A/B 测。>   
> **关键**：不要先改方案再找原因，**先定位再动手**。"

**Q15：你最大的缺点？**

> "**AI 产品业务的深度还在补**——我之前更多是 ToB SaaS 经验，没真正做过 C 端 AI 应用（豆包/Kimi/智书这类）。**主动在补**：在看 AIPM-Wiki 资料、拆解市面主流 AI 应用的产品设计。给我 1-2 个月能上手。"

## 一、这场面试的特殊性：AI 面试官

根据面试须知，这场是用 qtech 平台做的**线上 AI 面试**，跟真人面试有本质区别：

| 维度  | 真人面试       | AI 面试（本场）                   |
