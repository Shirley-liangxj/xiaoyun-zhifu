# 小云智服 — 需求分析与用户研究（v2.0）

> 基于v1文档升级 | 日期：2026-08-15
> 升级点：① 痛点引用8份真实客服对话截图 ② 每个关键决策附面试话术 ③ 定位收敛为"售后规则治理平台"

---

## 一、项目背景与痛点诊断

### 痛点1：人力断层——夜间与大促无人值守

- **场景**：中小卖家通常只有1-3名客服，夜间（22:00-08:00）不排班，大促期间咨询量翻3-5倍。
- **后果**：买家咨询没人回 → 等不及 → 退款/差评 → 店铺DSR评分受损。

### 痛点2：低效重复——70%咨询是简单重复问题

- **场景**：日常咨询高度集中在"发什么快递""多久到""怎么退货"等简单问题，占比60-80%。
- **后果**：客服把时间耗在复制粘贴标准答案上，没精力处理复杂纠纷。

### 痛点3：传统机器人体验差——"选择题式"僵化交互

- **真实证据**（拼多多诚少家的店截图）：
  - 买家问"怎么退货" → 机器人回"亲亲 欢迎光临 小店 有什么能为您效劳的呢~"（完全答非所问）
  - 买家问"卖家说三天发货怎么还没发" → 机器人回"现在下单，预计13小时内发货"（把已下单问题当成新下单推荐）
  - 买家说"转人工" → 机器人回"没有订单"（转人工机制失效）
- **结论**：用户要的是"对话解决"，传统机器人给的是"菜单导航"。

> **🎤 面试话术：为什么选这个方向？**
> "我分析了8份真实服饰电商客服对话，发现两个核心问题：一是中小店铺的平台机器人答非所问，连'怎么退货'都答不上；二是服饰类目退换货率20-30%，售后咨询量是其他类目的3-5倍。现有方案要么太贵（智齿/七鱼年费几万），要么是平台绑定的通用机器人（答非所问），中间存在一个'中小服饰商家用得起、答得准'的空白。"

## 二、为什么用RAG而不是纯大模型或纯规则

| 方案 | 缺陷 | 选择 |
|------|------|------|
| 纯规则机器人 | 僵硬、维护成本高、识别不了自然语言变体 | ❌ |
| 纯大模型直答 | 会编造店铺政策（幻觉）、答案不可溯源、答错要担责 | ❌ |
| **RAG（检索增强生成）** | 检索"店铺自己的售后政策文档"再回答，答案有出处、可更新、不编造 | ✅ |

> **🎤 面试话术：为什么用RAG而不是微调模型？**
> "三个原因：第一，售后政策会频繁更新（大促改规则、换季改退换货政策），微调一次要几天，RAG重新上传文档几分钟生效；第二，售后场景答错要担责（比如把'7天无理由'说成'15天'，商家要赔钱），RAG的来源溯源让每条回答有据可查；第三，成本——微调一个垂直模型几万块，RAG用API调用几毛钱。对中小商家来说，可更新、可溯源、低成本是硬约束。"

## 三、目标用户画像

### 3.1 商家端（付费决策方）

| 维度 | 描述 |
|------|------|
| **店铺类型** | 淘宝/抖音/拼多多客单价50-200元的服装、日用类中小店铺 |
| **经营规模** | 日均咨询量200-1000单，客服团队1-3人 |
| **典型状态** | 旺季依赖临时客服或熬夜加班，没有专职运营 |
| **核心诉求** | 降低客服人力成本、夜间/大促能接住咨询、不因为AI答错背锅 |
| **付费能力** | 年费预算<2000元（对标人工月薪3000-5000的零头） |

### 3.2 买家端（实际使用者）

| 维度 | 描述 |
|------|------|
| **身份** | 在服饰电商购物后有售后需求的消费者 |
| **核心诉求** | 秒回、答得准、答不了痛快转人工（而不是死循环） |
| **典型问题** | "怎么退货""运费谁出""快递到哪了""衣服质量有问题怎么办" |
| **痛点** | 机器人答非所问、转人工找不到入口、人工回复慢 |

### 3.3 非目标用户

- 日单量<50的微型店铺（咨询量太少，不需要AI）
- 日单量>2000的大店铺（已有成熟客服团队和系统，不是我们的客群）
- 非服饰类目（本产品内置服饰行业知识，不做通用客服）

> **🎤 面试话术：为什么目标用户是1-3人客服团队的中小商家？**
> "这是一个市场分层的选择。大商家有晓多/乐言，年费几万但服务到位；小商家用平台免费机器人，虽然难用但不花钱。中间的1-3人团队最尴尬——用不起企业级方案，又被免费机器人的答非所问折磨。他们的付费意愿最强（因为售后答错直接赔钱），付费能力刚好匹配我们的低价定位。"

## 五、核心产品指标（KPIs）

### 5.1 北极星指标

> **AI自主解决率（FCR）**：AI独立解决、无需人工介入的会话占比，目标 ≥ 65%。

**为什么选FCR作为北极星？** 它同时回答商家最关心的两个问题——"省了多少人力"（AI接住的越多，人力投入越低）与"体验好不好"（问题被真正解决才不会转人工）。是唯一同时绑定商家利益与买家体验的指标。

### 5.2 业务效果指标

| 指标 | 定义 | 目标 |
|------|------|------|
| AI自主解决率（FCR） | AI独立解决、无需人工介入的会话占比 | ≥ 65% |
| 人工转接率 | 买家主动或触发规则转人工的会话占比 | ≤ 25% |
| 平均响应时长 | 买家提问到收到有效答复的端到端耗时 | < 3秒 |
| 买家满意度（CSAT） | 会话结束后评价4-5星占比 | ≥ 85% |

### 5.3 AI技术体验指标

| 指标 | 评测口径 | 目标 |
|------|---------|------|
| 知识库召回率（Recall@K） | 检索Top-K（K=3）命中正确知识片段的比例 | ≥ 85% |
| 回答准确率（规则咨询类） | 政策/规则类问题与标准答案一致的比例 | ≥ 95% |
| 防幻觉拒答率 | 超纲问题成功拒答或转人工（而非编造）的比例 | 100%零编造 |

> **🎤 面试话术：防幻觉为什么是100%？**
> "售后场景和闲聊不一样。闲聊时AI编造一个答案，用户最多觉得不准；售后时AI把'7天无理由'说成'15天'，商家要按15天给客户退货，直接赔钱。所以我们的设计原则是：可以答不上来（拒答+转人工），但绝不能编造。这是ToB客服产品的信任底线。"

### 5.4 FCR口径定义（防"口径游戏"）

一次会话同时满足以下三个条件，才记为"AI独立解决"：

| 条件 | 判定标准 | 排除情形 |
|------|---------|---------|
| ① AI给出有效回答 | 回答命中买家问题（非拒答、非转人工、非仅安抚） | 未回答即转人工/只安抚不解决 |
| ② 买家未继续追问 | 回答后30分钟内未就同一问题再次提问 | 买家追问同一问题 |
| ③ 无后续投诉升级 | 会话未被投诉，48小时内未升级为差评/纠纷 | 关联差评、纠纷单、平台投诉 |

**明确不采用的口径游戏：**
- ❌ 静默即解决（买家不回话≠解决）
- ❌ 转人工前掐断（转人工必须真实接通）
- ❌ 非活跃时段注水（凌晨数据不混入日常均值）

> **🎤 面试话术：为什么要把FCR口径写这么细？**
> "我在竞品分析里发现，行业普遍存在'报表解决率≠真实解决率'的问题——有的厂商把'买家问完不回话'就算解决，有的在转人工前加挽留漏斗来压低转接率。我把口径写死，并且支持下钻到原始对话复核，这本身就是产品差异化：商家对'AI答得对不对'有掌控感，而不是看一个注水的数字。"

## 六、端到端工作链路设计（对应面试三问之一）

### 链路总览

```
买家提问 → 意图识别 → RAG检索 → 置信度评估 → 生成回答(带出处)
                                          ↓
                              置信度<阈值 → 拒答 + 转人工
```

### 每个环节的设计出发点

| 环节 | 设计出发点 | 为什么这么设计 |
|------|-----------|--------------|
| 意图识别 | 区分"政策咨询"vs"需要人工判断的纠纷" | 政策类可以AI答，纠纷类必须人工，混在一起会出问题 |
| RAG检索 | 从店铺自己的政策文档中检索相关片段 | 保证回答基于商家自己的规则，不是通用知识 |
| 置信度评估 | 检索相关性得分 × 回答长度系数 × 是否包含来源 | 量化"AI对这个回答有多大把握"，作为转人工依据 |
| 来源溯源 | 每条回答标注来自哪份文档的哪个片段 | 商家可核对、买家可信任、答错可追溯 |
| 转人工兜底 | 置信度低/连续拒答/用户要求/情绪负面时触发 | AI不硬撑，复杂问题交给人，保证体验底线 |

> **🎤 面试话术：你的端到端链路设计出发点是什么？**
> "整条链路围绕一个核心原则：'能答的自动答，不能答的快速转人工，不硬撑不编造'。意图识别是为了把可自动化的政策咨询和必须人工的纠纷分开；RAG+溯源是为了让回答有据可查；置信度评估是为了量化'AI有没有把握'，而不是让AI盲目回答；转人工是最后的安全兜底。每个环节都对应一个真实痛点，不是为了技术而技术。"
