## 1. 一句话定位（以代码为准，澄清与 00 文档的旧矛盾）

**小云智服是面向中小服饰电商的售后客服：高置信度时 AI 自主回复买家；低置信度不硬撑，转入人工队列兜底。转人工之后，最终发送权在坐席（采纳 / 编辑 / 手打）。**

| 路径 | 实际行为 | 旧文档容易写错的地方 |
|------|----------|----------------------|
| 买家端高置信（默认阈值 ≥ 0.6） | AI **直接把答案发给买家**（自主答） | 00 曾写成「AI 只做建议、人工确认后才发出」——那只描述**转人工后的坐席协同**，不是买家主路径 |
| 买家端低置信 / 无检索 / 投诉高危 | 拒答话术 + 会话进 `waiting_human` | 与「兜底」一致 |
| 坐席待人工会话 | AI 生成 **未发送** 的建议卡，坐席接入后才发出 | 这里才是「最终发送权在人工」 |
| 操作类（退款试算等） | 只算不打款，HITL 确认后再进人工队列 | 演示 mock，非真实支付 |

作品集 Demo，**非生产上线、未服务真实付费商家**。

## 3. 前端：已接页面 vs 规划 25 页

`App.jsx` 实际路由：`/chat` `/login` `/register` `/` `/conversations` `/tickets` `/knowledge` `/quick-replies` `/evaluation` `/settings`（约 10 页）。

规划页来自 `docs/03` 第七节。标注规则：

- **已实现**：独立路由或该页完整主流程可点  
- **部分实现**：能力嵌在别的页，或缺独立路由 / 缺规划中的关键字段  
- **规划未做**：无页面、无等价入口

## 6. 建议演示路径（给看不了仓库的人）

1. `/chat`：高置信政策题 → 看自主答 + 来源  
2. 低置信 / 投诉 → 待人工  
3. 坐席登录 → 接入 → 建议卡发送 → 买家轮询可见  
4. 「帮我把订单退了」→ 计划卡 + 确认（不打款）  
5. `/evaluation` 跑 67 题，讲转人工判断而非只讲回答准确率  

启动与账号见仓库根目录 `README.md`。
