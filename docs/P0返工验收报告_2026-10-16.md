# 小云智服 P0 返工验收报告

> 验收日期：2026-10-16  
> 触发依据：`docs/第三方补齐结果独立复核报告.md`  
> 证据优先级：当前源码与本轮实测 > 自动化测试 > 文档描述  
> 结论范围：仅指本地源码、本地临时环境和受控离线评测；不等于线上已更新。

## 1. 结论

第三方复核指出的 6 类 P0 缺口已在本地源码完成返工，并补上了原报告缺少的完整任务链和页面走查证据：

1. Agent 评测改为 mock 外部 LLM、执行真实 `run_agent_turn()` 和真实工具注册表，不再用 `_mock_plan()` 自问自答。
2. 退款从“买家确认即结束”改为结构化审核状态机：待买家确认 → 待坐席审核 → 批准/拒绝/补材料。
3. 采纳率区分原样采纳、编辑采纳、拒绝、待处理和自动发送，只以已处理建议为分母。
4. 知识缺口保留失败状态、原因、文档关联和版本；重试复用原文档，并验证真实 FAISS 写入与检索。
5. 活动评测脚本不再把关键词覆盖称为回答准确率；历史 JSON 仍保留原字段，但只作为历史口径归档。
6. 一条退款任务已跑通：工具试算 → 买家确认 → 坐席审核 → 买家收到结果 → 审计状态一致。

本地 P0 可以判定为通过。仍未完成的是部署层工作：没有推送 GitHub、没有重新部署阿里云、没有对线上页面复测。因此当前作品集和视频不能写成“线上已更新”。

## 3. Agent 离线评测的准确边界

当前 `eval/agent_cases.json` 有 12 条受控场景，运行方式为 `mock_llm_real_agent_loop`：

- 模拟的是外部 LLM 返回，避免网络、费用和模型随机性；
- 被测对象是真实 `run_agent_turn()`、工具参数校验、工具执行、中断逻辑、数据库状态和轨迹；
- `query_order`、`calc_refund`、`transfer_to_human` 走真实项目工具；
- RAG 外部返回使用受控 fixture；
- 因此可以证明控制层逻辑和回归边界，不能证明真实模型在线工具选择准确率。

本轮新鲜输出：

```text
total=12
execution_mode=mock_llm_real_agent_loop
tool_sequence_accuracy=100.0
parameter_accuracy=100.0
followup_accuracy=100.0
terminal_state_accuracy=100.0

```

其中 `agent FC loop failed: mock llm unavailable` 是“LLM 异常”用例故意触发的日志，不是测试运行失败。

## 4. 完整退款任务的状态与证据

本地闭环的真实状态变化为：

```text
calc_refund 试算
→ pending_buyer
→ 买家点击“确认提交给人工”
→ waiting_review
→ 坐席选择 approved / rejected / need_more_info
→ 买家看到审核结果
→ HumanReviewEvent 保留 buyer 与 agent 两段状态变化
```

约束：

- 退款只做演示试算和审核记录，不连接支付渠道，不执行真实退款；
- 缺订单号、金额或购买天数时进入 `needs_clarification`，不再默认补造 199 元、5 天或假订单号；
- 未知工具、工具参数错误和工具异常不能继续生成“已完成”，会进入明确兜底；
- 待审核会话不能通过普通接入接口绕过审核。

## 5. 页面走查记录

本轮使用独立临时 SQLite 数据库启动本地后端和前端，没有读取或修改现有业务库。

实际步骤与结果：

1. 用演示账号登录本地后台，进入会话管理。
2. 打开“页面验收买家”的待审核会话。
3. 页面显示订单号、订单金额、建议退款、风险原因和审核备注输入框。
4. 待审核时没有普通“接入”按钮，普通发送按钮禁用。
5. 输入“资料齐全，批准演示退款建议”并点击批准。
6. 审核卡变为“已批准”，会话从“待人工”变为“进行中”。
7. 坐席消息明确显示“本项目只记录审核结果，未执行真实退款”。
8. 公开买家接口读取同一会话，返回该最终审核消息。

本轮页面走查使用临时数据；它证明本地源码主路径可交互，不代表阿里云线上版本已经更新。
