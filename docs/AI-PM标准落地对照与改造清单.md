## 一、先给结论

小云的短板不是缺少更多页面，也不是缺一份更长的 PRD，而是四条证据链没有完全对齐：

```text
用户任务 → AI/规则机制 → 可见证据 → 评测/兜底 → 产品决策
```

外部标准真正要求的是“让面试官能复述你的判断并继续追问”，不是把所有文档都塞进作品集。

## 二、外部标准逐条落地

## 三、这些标准如何变成小云的一条主故事

### 核心角色

买家提出售后问题；坐席不是第二个独立故事，而是同一会话中系统在风险/不确定性出现后的协作者。

### 完整任务

1. 买家先问一个有标准答案的售后政策问题。
2. 系统检索知识库，展示答案依据/置信信号，并自动回复。
3. 同一会话再提出退款、投诉或曝光类灰度问题。
4. Agent 判断需要查询、计算、追问或转人工；高风险不直接执行。
5. 坐席接管并看到上下文、风险原因和建议处理方式。
6. 本次未命中或低置信度记录成知识缺口。
7. 知识缺口进入回归集，下一版用评测确认是否改善。

### 每一步必须展示的产品判断

| 步骤 | 不要只展示 | 必须说清 |
|---|---|---|
| 检索回答 | “模型回答了” | 为什么这个问题允许自动回答、证据从哪来 |
| 风险问题 | “回答失败了” | 为什么系统主动停下、停在什么边界 |
| 工具调用 | “用了 Function Calling” | 为什么选这个工具、工具能做什么/不能做什么 |
| 人工接管 | “转人工了” | 坐席拿到了什么上下文，如何降低重复沟通 |
| 知识缺口 | “有数据飞轮” | 哪条记录如何变成文档/题目/版本回归 |
| 评测 | “准确率很高” | 题目版本、样本、口径、失败类型和下一决策 |

## 四、当前已实践 / 只写入规则 / 还缺什么

### 已验证的事实

- 当前题库为 40 题；历史 67 题不作为当前线上题库。
- 当前 Agent 工具包括政策检索、订单查询、退款计算、转人工。
- 退款计算当前不执行资金动作。
- 高风险和不确定场景存在人工接管边界。
- 项目有 RAG、置信度/风险分流、知识缺口和离线评测相关材料。

### 已写入项目规则但还没有形成新公开产物

- 视频必须用“一个买家、一个任务、一路展示机制与价值”的叙事。
- 作品集首屏只承担 30 秒理解，不堆完整报告。
- PRD 只展示能证明判断的用户故事、状态、异常、工具契约和验收标准。
- 下一步必须写问题、动作、指标/验收线、达标后决策。

### 仍需真实执行的改造

| 优先级 | 改造 | 验收线 |
|---|---|---|
| P0 | 录制单主线视频 | 配音每句话都能对应一个实际画面和证据；不再出现三个页面各讲一段的断裂 |
| P0 | 补 Agent 轨迹评测 | 至少覆盖工具选择、追问、转人工三类；每题有预期轨迹和失败归因 |
| P0 | 统一作品集口径 | 页面不再出现无标签 67 题、未核验数字或把建议说成执行 |
| P1 | 知识缺口闭环 | 每条缺口有来源、状态、回归题 ID、版本和复测结果 |
| P1 | 坐席可用性验证 | 用 3–5 个代表性任务做可用性观察，记录完成时间、重复输入和误接管 |
| P2 | 只读真实系统接入 | 先接物流/订单只读接口；验收是来源可追溯、权限可控、失败可转人工 |

## 五、作品集改造验收

作品集可以交付给 HR 的条件：

- [ ] 首屏 30 秒说清岗位定位、项目、核心任务和入口。
- [ ] 主案例只保留一个完整任务链，不用功能清单串场。
- [ ] 页面同时有可运行 Demo/视频、架构/流程、PRD 节选、评测证据、badcase 和下一步。
- [ ] 每个数字有样本、口径、日期；不能复算就降级为定性描述。
- [ ] 40/67、Demo/线上、计算/执行、已实现/设计中都有明确标签。
- [ ] “我的贡献”是产品决策、机制定义、评测和推进，不把 AI 生成代码全部算成个人成果。
- [ ] 下一步都能回答“现在为什么做、怎么测、达标后做什么”。

## 六、视频改造验收

- [ ] 0–15 秒：定位、用户、任务、价值。
- [ ] 15–45 秒：标准问题自动回答，展示证据。
- [ ] 45–90 秒：同一会话进入灰度问题，展示 Agent/风险边界。
- [ ] 90–125 秒：坐席接管，展示上下文和协作价值。
- [ ] 125–155 秒：知识缺口/评测，说明失败如何回流。
- [ ] 155 秒后：当前边界、已证明什么、下一步如何验证。
